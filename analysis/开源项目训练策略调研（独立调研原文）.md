## Section A — Most relevant projects

### A1. Hu, Tang, Wang, Li, Li & Zeng (2025), hard shoulder running with MADDPG + emergency vehicles — **the closest existing work to this project**

- Paper: *Journal of Intelligent Transportation Systems*, [publisher page](https://www.tandfonline.com/doi/full/10.1080/15472450.2025.2543823), author-hosted PDF: [hu2025jits.pdf](https://sunderlandaj-1130.github.io/files/hu2025jits.pdf) — **[paper]**
- **Not a repository.** No code release is referenced in the paper.
- **What it does:** LSTM feature extraction + MADDPG with prioritized experience replay and importance sampling
  to decide hard-shoulder running (HSR) on a 6.2 km section of the Jinan City Ring Highway, 16 sub-sections,
  with an improved A* clearing the shoulder for emergency vehicles. SUMO.
- **Why it matters for comparability:** it is the only located published work whose action space is literally
  *open/close the shoulder*, and it is **discrete** — "each agent controls two consecutive road segments"
  (p.13, 5.1.1), action = the 4 discrete open/closed combos {(0,0),(0,1),(1,0),(1,1)} (p.13, 5.1.2), state
  `S_i=[s_agent_i, s_environment]` with `s_agent_i=[c,w,v,tt,occ]` (p.13–14, 5.1.3). Agent count is never
  given numerically; the text implies 8.

Training-strategy details (items 1–8):

1. **Exploration:** ε-greedy only — "selects the actions through the 'ε-greedy' methodology" (p.10, 4.2). No
   OU/Gaussian term, and **no ε value, no schedule, no start/end** stated anywhere. → largely *not found*.
2. **Entropy:** **not found** — LOSS eq.(1) (p.10) has no entropy bonus; the three named training measures
   (p.12, 4.4) are PER, IS, Credit Assignment. The word "entropy" appears once, in a bibliography title.
3. **Target networks:** soft update for actor and critic — "ϑ_Qi' = (1-∂)ϑ_Qi + ∂ϑ_Qi'" (p.10, eq.3–4; Fig.6 p.11)
   — but **the value of ∂ (tau) is not given**. One critic per agent, so **no twin critics**; **no target policy
   smoothing**; **no delayed policy update**.
4. **Reward/return:** γ appears only as a symbol, **value not given**. 1-step TD target. No reward
   normalization/scaling/clipping; reward is a hand-weighted sum of log10 terms (p.14, 5.1.4, eq.14–18).
5. **Optimizer/buffers:** actor lr, critic lr, grad clipping, batch size, buffer size, warm-up — **all not found**.
   Adam is never even named. PER and IS appear only as formulas with symbolic hyperparameters α, β, T (p.12, 4.4).
6. **Best-model selection:** **not found.** Training is 1000 epochs (Fig.10, p.16); no checkpoint rule described.
7. **Evaluation:** 10 runs per strategy per service level, averages taken (p.16, 6.2). **Seeds not stated;
   deterministic-policy evaluation not stated.**
8. **Stability tricks:** only "Credit Assignment (CA) … helps prevent the occurrence of lazy agents" (p.12, 4.4)
   and importance sampling to correct PER bias. No LR decay, no KL, no entropy annealing.

**Companion paper** (same group, STC-MADDPG): *Alexandria Engineering Journal* 117 (2025) 99–115,
[author-hosted PDF](https://sunderlandaj-1130.github.io/files/hu2025.pdf) — **[paper]**. Same task family
(6.5 km Jinan section, 16 sub-sections, binary open/close action; 8 agents if each controls 2 sub-sections,
4 agents if each controls 4 — p.108). Adds: additive exploration noise as a **symbol only** —
"a_i = σ_i(s_i(t);β^σ) + N_a" (Algorithm 1, line 6, p.105), **noise family unnamed, no schedule, no
start/end value**; soft target update "every N training times" with **N not given** and θ value not given;
γ value not given; learning rates, batch size, buffer capacity **not found**; 200 training epochs (Fig.7, p.107);
**no best-model selection and no seed/eval protocol stated**. It does claim "to ensure training stability, a
single agent is equipped with a dual Actor-Critic framework, wherein each agent has two Actor networks and two
Critic networks" (p.103, 4.2).

**Takeaway for Section C:** the single most comparable publication is *less* specified than this project — it
does not report entropy, tau, γ, learning rates, buffer size, checkpoint selection or seeds. It therefore offers
no evidence that this project's entropy_coef=5.0 or best-episode checkpointing is standard. It does establish
that **discrete open/close shoulder actions with a MADDPG-family learner is a legitimate, publishable
formulation**, and it independently names two stabilisers this project lacks: PER+IS correction and explicit
lazy/dead-agent mitigation.

### A2. `shariqiqbal2810/maddpg-pytorch` — reference MADDPG **with a discrete-action path** — https://github.com/shariqiqbal2810/maddpg-pytorch

**691 ★** (read from `https://gh-proxy.com/https://api.github.com/repos/shariqiqbal2810/maddpg-pytorch`, cross-checked
against `https://img.shields.io/github/stars/shariqiqbal2810/maddpg-pytorch.json`) — **[W,3p]**

PyTorch reference MADDPG for MPE. Its relevance here is specific: of the two popular MADDPG reimplementations,
only this one has real discrete support. A full grep for `discrete|gumbel|Gumbel|softmax` over all `*.py` in
`starry-sky6688/MADDPG` (683 ★) returned **no matches** — that fork is continuous-only — **[W]**.

1. **Exploration:** continuous → Ornstein-Uhlenbeck, `OUNoise(action_dimension, scale=0.1, mu=0, theta=0.15, sigma=0.2)`
   (`utils/noise.py` L6), with the **scale annealed linearly from `--init_noise_scale 0.3` to
   `--final_noise_scale 0.0` over `--n_exploration_eps 25000` episodes**: `explr_pct_remaining = max(0, config.n_exploration_eps - ep_i) / config.n_exploration_eps` then
   `maddpg.scale_noise(final + (init - final) * explr_pct_remaining)` (`main.py` L71–72), reset per episode.
   Discrete → the policy emits Gumbel-Softmax samples: `action = gumbel_softmax(action, hard=True)`
   (`utils/agents.py` L67). A field `self.exploration = 0.3  # epsilon for eps-greedy` exists (`agents.py` L42)
   and is annealed by the same 0.3→0.0 schedule, but **it is not used for action selection** — **[W]**.
2. **Entropy:** **not found in repo** — no entropy bonus or coefficient. The only policy regularizer is a
   **constant** L2 penalty on the policy output, `pol_loss += (curr_pol_out**2).mean() * 1e-3`
   (`algorithms/maddpg.py` L161) — **[W]**.
3. **Target networks:** `hard_update` of target policy and critic at construction (`utils/agents.py` L35–36), then
   **soft update with `--tau` default 0.01** after every agent update (`algorithms/maddpg.py` L173–181,
   `main.py` L143). **No twin critics, no target policy smoothing, no delayed policy update** — every agent is
   updated at each `--steps_per_update=100` env-step boundary (`main.py` L90–101) — **[W]**.
4. **Reward/return:** no normalization, scaling or clipping anywhere. 1-step TD target with done mask
   (`algorithms/maddpg.py` L118–120). **gamma = 0.95**, a class default that `main.py` never overrides
   (`maddpg.py` L15) — **[W]**.
5. **Optimizer/buffers:** **one** `--lr` shared by actor and critic, Adam, **default 0.01** (`utils/agents.py` L37–38).
   **Gradient clipping 0.5** on both nets (`maddpg.py` L131, L165). **batch 1024**, **buffer 1e6**, episode_length 25,
   n_episodes 25000. **No learning-starts parameter**; updates begin once the buffer holds a batch
   (`main.py` L90–91) — **[W]**.
6. **Best-model selection:** **none** — periodic only: `--save_interval 1000` writes `incremental/model_ep%i.pt`
   and overwrites `model.pt`, plus a final save (`main.py` L108–113) — **[W]**.
7. **Evaluation:** `evaluate.py` loads `model.pt` or `--incremental <ep>`; **`--n_episodes` default 10**,
   `--episode_length 25`; **deterministic on purpose**: `maddpg.step(torch_obs, explore=False)` (`evaluate.py` L44)
   → `onehot_from_logits` for discrete, no OU noise for continuous (`agents.py` L64–75). **No `--seed` in
   `evaluate.py`**; training seeds via `--seed 1` (`main.py` L21) — **[W]**.
8. **Stability tricks:** `nn.BatchNorm1d` input normalization on every network (`utils/networks.py` L19–22);
   small final-layer init for the continuous actor `uniform_(-3e-3, 3e-3)` with the comment
   "initialize small to prevent saturation"; hard target init; grad-norm clip 0.5; 1e-3 L2 output penalty;
   `(1 - dones)` masking in the target; and an explicit note that discrete policies are trained through the hard
   Gumbel-Softmax because "discrete policies don't seem to learn properly without it" — **[W]**.

### A3. `uoe-agents/revisiting-maddpg` — research reference for **discrete-action MADDPG** — https://github.com/uoe-agents/revisiting-maddpg

**29 ★** (from `https://img.shields.io/github/stars/uoe-agents/revisiting-maddpg.json`) — **[W,3p]**. Default branch is `main`.
Paper: *Revisiting the Gumbel-Softmax in MADDPG* (ALA 2023), [arXiv:2302.11793](https://arxiv.org/abs/2302.11793) — **[paper]**, read via [ar5iv HTML](https://ar5iv.labs.arxiv.org/html/2302.11793).

Directly relevant: it isolates *only* the discrete gradient estimator for a MADDPG-family learner with per-agent
one-hot `Discrete(n)` actions (`maddpg.py` L27–28), which is this project's exact action regime.

1. **Exploration:** **no epsilon-greedy and no added action noise.** The behaviour action is
   `torch.argmax(gs_output, dim=-1)` on a sampled one-hot (`agent.py` L49–52) — i.e. a categorical draw from
   `softmax(logits)`. The paper states the discrete estimator itself supplies exploration: "in discrete cases, the
   STGS itself provides some degree of exploration, since relaxing the distribution places some probability mass
   onto other actions … the amount of exploration is controlled by the temperature parameter" (L95). The one
   schedule present is TAGS **exponential temperature annealing**: `self.multiplier = (end_temp / start_temp) ** (1 / period)`
   (`gradient_estimators.py` L39–46), with per-env settings LBF 4.0→0.1 over 3e6, RWARE 1.0→0.3 over 4e6,
   MPE 2.5→0.5 over 2e6 (`config/final_params/*/*-tags.yaml`) — **[W]**.
2. **Entropy:** **no entropy bonus and no alpha anywhere.** The only policy-side regularizer is a **constant** L2
   penalty on raw logits: `loss += (policy_outputs ** 2).mean() * self.policy_regulariser` (`agent.py` L82–83),
   coefficient `--policy_regulariser` default 0.001 (`main.py` L212), MPE final config 0.01 — **[W]**.
3. **Target networks:** **soft Polyak, `--soft_update_size` default 0.01** (`main.py` L211;
   `agent.py` L90–92; `networks.py` L20–22), plus a hard copy at init. **No target policy smoothing**
   (`agent.py` L54–57 feeds an unperturbed target action), **no twin critics** (single `CriticNetwork`,
   `agent.py` L40), **no delayed policy update** (`maddpg.py` L84–99) — **[W]**.
4. **Reward/return:** **optional online reward standardisation** — `--standardise_rewards` (`main.py` L214) with
   `RunningMeanStd` updating mean/var (`maddpg.py` L46, L79–81). **No clipping.** 1-step target (`agent.py` L63–64).
   **gamma = 0.95** (`main.py` L210; no yaml overrides) — **[W]**.
5. **Optimizer/buffers:** `--actor_lr` / `--critic_lr` both **3e-4** default (`main.py` L207–208), Adam with
   `eps=0.001` (`agent.py` L46–47); final configs raise both to **5e-4** (MPE/RWARE). **Grad clip 1.0** on both nets
   (`agent.py` L71, L87). **batch 512** (`main.py` L205). **buffer 2,000,000** (`main.py` L199).
   **Warm-up 400 random-action episodes** (`main.py` L198, L107–114) — the most explicit learning-starts value
   found in any repo here — **[W]**.
6. **Best-model selection:** **none** — one final `torch.save(maddpg.agents, "saved_agents/maddpg_{env}_{time}.pt")`
   after the training loop (`main.py` L176–178). `eval_returns` is accumulated but never used to select a model — **[W]**.
7. **Evaluation:** every **50,000 env steps, 100 episodes**, reporting the mean (`main.py` L217–218, L141–153).
   Paper L150: "we evaluate the achieved returns 100 times every 50 000 time-steps. Each training iteration is done
   over five random seeds and a 95% confidence interval is calculated." **Not deterministic** — evaluation reuses the
   same sampling behaviour policy (`action_fn=maddpg.acts`, `main.py` L150) — **[W]**.
8. **Stability:** grad-norm clip 1.0, Polyak tau 0.01, optional reward standardisation, L2 logit regularizer,
   **replay sampling without replacement** (`buffer.py` L41–45), and gradient-variance logging
   (`main.py` L134–139). No LR decay, no KL, no dead-agent handling — **[W]**.
   Paper findings worth quoting to the team: GST "achieving 55% higher maximum returns over the baseline, and over
   double the average returns" (L213); TAGS "as it was presented here, should not be used" (L249); and
   "we agree that the bias of the STGS method is indeed problematic for MADDPG" (L281).

### A4. `marlbenchmark/on-policy` — MAPPO reference implementation — https://github.com/marlbenchmark/on-policy

**2109 ★** — read from `https://api.github.com/repos/marlbenchmark/on-policy` (my own call) and re-confirmed via
`gh-proxy.com` + `ungh.cc` — **[A]/[W,3p]**. README fetched directly by me from
[cdn.jsdelivr.net](https://cdn.jsdelivr.net/gh/marlbenchmark/on-policy@main/README.md) — **[A]**.

This is where the entropy-coefficient comparison is sharpest.

1. **Exploration:** **not found in repo.** No epsilon, no action noise, no noise schedule — a repo-wide grep for
   `epsilon|action_std|log_std|OrnsteinUhlenbeck|exploration|noise` finds only ValueNorm's epsilon, an optimizer-eps
   help string, and env-side `u_noise = None`. Exploration is categorical sampling,
   `actions = action_logits.mode() if deterministic else action_logits.sample()`
   (`onpolicy/algorithms/utils/act.py` L86–89) — **[W]**.
2. **Entropy:** **used, `entropy_coef`, default 0.01, constant, never annealed.** `onpolicy/config.py` L249–250:
   `parser.add_argument("--entropy_coef", type=float, default=0.01, help='entropy term coefficient (default: 0.01)')`,
   applied as `(policy_loss - dist_entropy * self.entropy_coef).backward()`
   (`onpolicy/algorithms/r_mappo/r_mappo.py` L145–146). A repo-wide grep for `entropy_coef` finds only its
   definition and its uses — **no decay, no clipping, no target entropy, no adaptive alpha** — **[W]**.
   Other PPO values: `ppo_epoch` 10 (spread) / 15 (comm, reference), `num_mini_batch` 1, `clip_param` 0.2 — **[W]**.
3. **Target networks:** **not found in repo** — no target networks at all. A repo-wide grep for
   `target_|tau|soft_update|polyak|delayed|TargetNet` returns 82 matches, *all* of which are StarCraft/Hanabi
   environment concepts; `tau`, `soft_update`, `polyak`, `delayed` appear zero times. Exactly one critic
   (`rMAPPOPolicy.py` L28–29); actor and critic optimized in the same `ppo_update` call (`r_mappo.py` L143–167) — **[W]**.
4. **Reward/return:** `gamma` **0.99**, `gae_lambda` **0.95**, `use_gae` True (`config.py` L257–262). **No reward
   normalization/scaling/clipping** in the learner — rewards are stored verbatim (`utils/shared_buffer.py` L81–82,
   L114) and used raw in the GAE recursion (L236–240). What *is* normalized is the **value target** via `ValueNorm`
   (`r_mappo.py` L64–67, `utils/valuenorm.py` L11 `beta=0.99999, epsilon=1e-5`) and **advantages are whitened**
   with NaN-masking for inactive agents (`r_mappo.py` L183–187). Reward scaling exists only env-side for SMAC
   (`envs/starcraft2/StarCraft2_Env.py` L96–97, L593–594) — **[W]**.
5. **Optimizer/buffers:** `--lr` default 5e-4, `--critic_lr` default 5e-4, Adam `eps=1e-5`, `weight_decay=0`
   (`config.py` L224–230); **MPE scripts override both to 7e-4**. `--max_grad_norm` **default 10.0** (note: its help
   string wrongly says 0.5), applied to actor *and* critic (`r_mappo.py` L148–149, L162–163). `episode_length` 25 and
   `n_rollout_threads` 128 for MPE (`train_mpe_*.sh` L20–21), `data_chunk_length` 10 → 128×25×3 = 9600 transitions per
   update for simple_spread. **No learning-starts / warm-up parameter exists**; training starts after the first
   rollout (`mpe_runner.py` L16–22) — **[W]**.
6. **Best-model selection:** **none.** A repo-wide grep for `best` (all file types) returns **no matches at all**.
   Checkpoints are written every `save_interval` (default 1) episode plus the final episode
   (`mpe_runner.py` L45–47), each overwriting the same `actor.pt` / `critic.pt` (`base_runner.py` L143–151).
   Eval rewards are printed and logged but **never compared or stored** (`mpe_runner.py` L178–183) — **[W]**.
7. **Evaluation:** `--use_eval` default **False**; when on, every `--eval_interval` 25 episodes (`mpe_runner.py` L77–79).
   The MPE runner **ignores `eval_episodes` (default 32)** and instead runs exactly one `episode_length`-long episode
   per `n_eval_rollout_threads` (default 1) — `mpe_runner.py` L144–149. **Deterministic:** `deterministic=True`
   (L151–154). **Fixed seeds:** `env.seed(all_args.seed * 50000 + rank * 10000)` for eval and `+ rank * 1000` for
   training (`train_mpe.py` L43, L25), global seed default 1 (`config.py` L164), `cuda_deterministic` on by default — **[W]**.
8. **Stability:** linear LR anneal **implemented but default-off** (`--use_linear_lr_decay` default False;
   `utils/util.py` L17–21 decays to zero); **no KL constraint in MAPPO** — `kl_threshold` (default 0.01) is referenced
   only by the TRPO trainer; `ValueNorm` on by default; **Huber loss on** (`--huber_delta` 10.0);
   **clipped value loss on** (`--use_clipped_value_loss`, clip 0.2); grad norm 10.0; `active_masks` dead-agent
   handling exists but is effectively all-ones for MPE — **[W]**.

### A5. `oxwhirl/pymarl` — QMIX/VDN/IQL reference implementation — https://github.com/oxwhirl/pymarl

**2223 ★** — read from `https://api.github.com/repos/oxwhirl/pymarl` (my own call, `"stargazers_count":2223`) and
re-confirmed via `gh-proxy.com` — **[A]/[W,3p]**.

The best available model for *how to evaluate and checkpoint*, and for discrete-action exploration.

1. **Exploration:** **ε-greedy, linear anneal, then flat.** `epsilon_start: 1.0`, `epsilon_finish: 0.05`,
   `epsilon_anneal_time: 50000`, `action_selector: "epsilon_greedy"` — identical in
   `src/config/algs/qmix.yaml`, `vdn.yaml`, `iql.yaml` (L4–7). The shape is linear because the selector constructs
   `DecayThenFlatSchedule(..., decay="linear")` (`src/components/action_selectors.py` L40–41) and
   `src/components/epsilon_schedules.py` L18–27 evaluates `max(self.finish, self.start - self.delta * T)` →
   ε(T) = max(0.05, 1.0 − (0.95/50000)·T), floored at **0.05 forever**. Anneal time is in **environment timesteps**
   (`basic_controller.py` L22–23; `episode_runner.py` L100–101) — **[W]**.
2. **Entropy:** **not found in repo.** A case-insensitive grep for `entropy` across all 48 files returns **zero
   matches**; no config has an entropy key; the QMIX/VDN/IQL loss is pure masked L2 TD error
   (`src/learners/q_learner.py` L97 `loss = (masked_td_error ** 2).sum() / mask.sum()`) — **[W]**.
3. **Target networks:** **hard periodic copy every 200 episodes, effective tau = 1.0.**
   `target_update_interval: 200` (`qmix.yaml` L13–14) triggered on the episode counter
   (`q_learner.py` L105–107), implemented as a full state copy (`_update_targets`, L118–121). **No soft tau**
   (a grep for `tau|soft_upd|polyak` matches only the word "trademarks" in LICENSE), **no target policy smoothing,
   no twin critics, no delayed policy update.** Overestimation is addressed instead by **double-Q action selection**,
   `double_q: True` (`qmix.yaml` L19; `q_learner.py` L71–76) — **[W]**.
4. **Reward/return:** **none** — rewards consumed raw (`q_learner.py` L39); strictly **1-step** target
   (`targets = rewards + self.args.gamma * (1 - terminated) * target_max_qvals`, L85–86); **gamma 0.99**
   (`src/config/default.yaml` L30). No return standardisation, no PopArt, no clipping. Reward shaping exists only as
   SMAC env arguments (`src/config/envs/sc2.yaml` L16–23: `reward_scale: True`, `reward_scale_rate: 20`) — **[W]**.
5. **Optimizer/buffers:** RMSprop **lr 5e-4**, `optim_alpha` 0.99, `optim_eps` 1e-5 (`default.yaml` L33–37);
   **grad-norm clip 10** (`grad_norm_clip`, applied `q_learner.py` L102); **batch 32 *episodes***, **buffer 5000
   *episodes*** (`qmix.yaml` L11, `default.yaml` L31–32); **learning-starts = 32 episodes** via
   `can_sample(batch_size)` → `episodes_in_buffer >= batch_size` (`episode_buffer.py` L231–232, `run.py` L169–179);
   uniform sampling **without replacement** (`episode_buffer.py` L239–241); no prioritised replay anywhere — **[W]**.
6. **Best-model selection:** **not found in repo** — no best-episode, no moving average, no best-checkpoint tracking
   (a grep for `best|best_model|best_episode|moving_average|ema` finds only unrelated comments). What exists is
   **periodic timestep snapshots** (`save_model_interval: 2000000`, default `save_model: False`; `run.py` L194–199)
   and test-return logging (`episode_runner.py` L115–118); loading picks by **timestep, not score**
   (`run.py` L135–140) — **[W]**.
7. **Evaluation:** greedy test runs of **`test_nepisode` 32 episodes every `test_interval` 10000 timesteps**
   for SC2 (`src/config/envs/sc2.yaml` L34–36; defaults 20 / 2000 in `default.yaml` L9–11), driven by
   `run.py` L182–192. **Deterministic/greedy:** `test_mode` forces `self.epsilon = 0.0`
   (`action_selectors.py` L49–51) so the masked argmax is taken (L61). Test episodes do not advance `t_env`
   (`episode_runner.py` L100–103). Single seed written into numpy, torch and the env (`main.py` L28–32); the seed
   *value* is supplied by Sacred and is not in the repo — **[W]**.
8. **Stability:** grad-norm clip 10; hard target resync every 200 episodes; double-Q; loss normalized only over
   valid non-padded elements with terminal steps masked out (`q_learner.py` L42–43, L97); unavailable actions
   hard-masked (−9999999 for targets, −inf for selection); batch truncated to the filled horizon (`run.py` L172–174).
   **Explicitly absent: entropy, reward/value normalization, LR decay, Polyak averaging, twin critics, delayed
   policy updates, target smoothing, prioritised replay, early stopping** — **[W]**.

### A6. `Ronchy2000/Multi-agent-RL` — MATD3 (continuous) with documented TD3 tricks — https://github.com/Ronchy2000/Multi-agent-RL

**441 ★** — read from `https://gh-proxy.com/https://api.github.com/repos/Ronchy2000/Multi-agent-RL`, cross-checked
at `https://img.shields.io/github/stars/Ronchy2000/Multi-agent-RL.json` — **[W,3p]**. Target dir `MATD3_Continous/`.

Useful as the *contrast case*: it is what MADDPG looks like after TD3's stabilisers are added.

1. **Exploration:** Gaussian per agent, **constant in practice** — `noise = torch.randn_like(action) * self.noise_std + self.noise_mean`
   then `noise = torch.clamp(noise, -0.2, 0.2)`, `noise_std=0.1` (`MATD3_agent.py` L94–95, L38–39). An unused
   decay mode exists (`noise_scale = max(self.min_noise, self.noise_scale * (self.decay_rate ** total_step))`,
   `decay_rate=0.999999`, `min_noise=0.01`, L90) but the runner hardcodes `noise_type='gaussian'`

### A16. Technique-level reference: the discrete-MADDPG gradient-estimator question

`uoe-agents/revisiting-maddpg` (A3) is the reference implementation for the specific problem of **MADDPG with
Discrete actions**, because its whole contribution is swapping the discrete gradient estimator while holding the
rest fixed. Its paper ([arXiv:2302.11793](https://arxiv.org/abs/2302.11793)) concludes that the Gumbel-Softmax
estimator's bias "is indeed problematic for MADDPG" and that GST — replacing the Gumbel randomness with two
deterministic perturbations — gave "55% higher maximum returns over the baseline, and over double the average
returns" in its benchmarks — **[paper]**. This is directly relevant if this project's softmax actor gradient is
being taken through the sampled discrete action.

Separately, single-run reporting is common but weak — the closest published analogue (the hard-shoulder paper) averages 10 runs. |
| 8 | **Long-run stability tricks** | Not specified beyond the entropy term; the observed failure is reward peak ~ep 600–800 then degradation. | **Gradient clipping**: 0.5–10 in 7 of the surveyed codebases. **LR decay**: implemented in MAPPO (`--use_linear_lr_decay`, **default off**), used by `mpcrl` (exponential 0.925/update), available-but-unused in ramp-metering TD3 (`ExponentialLR` imported, never stepped). **KL constraint**: **absent from MAPPO** (kl_threshold is TRPO-only) and absent everywhere else. **Dead/lazy-agent handling**: named as "Credit Assignment" in the JITS hard-shoulder paper; `active_masks` NaN-masking of advantages in MAPPO; next-state padding for missing agents in `cinglelas`. **Other**: batch truncation to filled horizon (pymarl); loss normalized only over valid elements (pymarl); replay sampling without replacement (pymarl, ramp-metering TD3, revisiting-maddpg); input BatchNorm (maddpg-pytorch); orthogonal init (MARL-code-pytorch); Huber + clipped value loss (MAPPO); optional reward standardisation (revisiting-maddpg); deliberate removal of exploration (SUMO-DVSL). **Documented instability:** `sac_vsl`'s own report notes downstream-speed oscillations and recommends a longer control step; `MARL-code-pytorch` comments that its eval metric "并不准确" (is not accurate). | **Gradient clipping is the most conspicuous omission** relative to comparable projects, and it is exactly the mechanism that bounds the late-training divergence this project observes. **The entropy coefficient is the second**: at 5.0 the policy sits near-uniform, so what the learner is optimizing is dominated by an entropy term that never shrinks, and there is no schedule to shrink it. |
| 9 | **Novelty check** | CA (Nagel-Schreckenberg) highway + RL, 3 lanes, ring, 1000 cells, emergency lane with yielding rules. | **Searches for a repo combining a Nagel-Schreckenberg-style highway CA with RL found none.** Ten GitHub repo-search queries returned **zero** repos combining an NS highway CA with RL; the closest verified items are `elbecerasaro/gym-cellular-automata` (48 ★, generic CA environments, **not** NS highway) and `flxwu/Traffic-Simulation-ABM` (15 ★, freeway NS cellular automaton + agent-based modelling, **no RL mention found**). | 10 | **Hard-shoulder-running domain** | Emergency lane open/closed per segment, 5 agents. | The only located comparable work is **published as a paper with no code release** (A1), and it is **less specified than this project** on almost every training item: no entropy, no ε value, no tau value, no γ value, no learning rates, no batch size, no buffer size, no checkpoint rule, no seeds, no deterministic-eval statement. ## Section C — Ranked, low-risk changes to the **training strategy**

These touch only the optimisation/exploration/evaluation machinery — **not the reward function**. Each is ranked by
(expected effect on the ep-600–800 peak-and-degrade failure) ÷ (risk of breaking a working submission).

> **Mechanistic hypothesis (state it as a hypothesis, not a finding):** with a constant entropy coefficient of 5.0,
> the entropy term dominates the policy objective, so the actor gradient is mostly the gradient of "stay uniform".
> That both (a) suppresses the very improvement the run is supposed to show and (b) makes the small
> policy-improvement component of the gradient a small residual on top of a large, near-constant term. If the
> relative weight of the entropy term drifts as returns grow — or if the policy is being pushed toward determinism
> late in training — the effective learning signal changes character mid-run, which is a plausible source of a
> peak followed by decay. I cannot verify this mechanism from the repos; I can verify that **no comparable
> project holds an entropy coefficient anywhere near 5.0**.

**C1. Lower `entropy_coef` by ~2–3 orders of magnitude, and anneal it down instead of holding it constant.**
Start near **0.01** (the explicit MAPPO default) or anneal **~0.05 → 0.001** across the run.
Evidence: MAPPO defines `entropy_coef` with **default 0.01** ([config.py L249–250](https://cdn.jsdelivr.net/gh/marlbenchmark/on-policy@main/onpolicy/config.py)) and applies it as a plain constant
([r_mappo.py L145–146](https://cdn.jsdelivr.net/gh/marlbenchmark/on-policy@main/onpolicy/algorithms/r_mappo/r_mappo.py)); four of the six comparable MADDPG/MATD3/TD3 codebases use **no entropy term at all**
(pymarl, maddpg-pytorch, MARL-code-pytorch, SUMO-DVSL, ramp-metering TD3), and the two PPO examples that do use
it use 0.1 (`sumo-rl`, [ppo_4x4grid.py L60](https://github.com/LucasAlegre/sumo-rl)) and ~0.09
(`sumo-rl` SB3 example) — with **no annealing anywhere in the survey**. Annealing is the standard MARL idiom applied
to the analogous quantity: **temperature in discrete-action MADDPG-family learners is annealed exponentially**
(`revisiting-maddpg`, `gradient_estimators.py` L39–46, with per-env schedules 4.0→0.1 / 2.5→0.5 / 1.0→0.3, and the
paper's "TAGS" method is *defined* as annealing the temperature down over training). *Why it plausibly fixes the
decay:* it removes a large, near-constant term from the actor objective, so late-training updates are driven by the
actual policy gradient rather than by an entropy term that keeps the policy uniform; and annealing specifically
matches the observed pattern of a mid-run peak followed by drift. *Risk:* low — one scalar; keep a copy of the old
config to revert.

**C2. Add a deterministic (argmax) evaluation path and select the checkpoint from it, not from training rollouts.**
Evidence: this is what nearly every comparable project does — pymarl sets `self.epsilon = 0.0` in test mode so
actions are the masked argmax ([action_selectors.py L49–51](https://cdn.jsdelivr.net/gh/oxwhirl/pymarl@master/src/components/action_selectors.py)); MAPPO evaluates with `deterministic=True`
([mpe_runner.py L151–154](https://cdn.jsdelivr.net/gh/marlbenchmark/on-policy@main/onpolicy/runner/shared/mpe_runner.py)); maddpg-pytorch with `explore=False` → `onehot_from_logits`
([agents.py L64–75](https://cdn.jsdelivr.net/gh/shariqiqbal2810/maddpg-pytorch@master/utils/agents.py), [evaluate.py L44](https://cdn.jsdelivr.net/gh/shariqiqbal2810/maddpg-pytorch@master/evaluate.py)); MARL-code-pytorch with `noise_std=0` and the comment
"We do not add noise when evaluating" ([maddpg_matd3_main.py L123](https://cdn.jsdelivr.net/gh/yongqingzs/MARL-code-pytorch@main/algorithms/maddpg_matd3_mpe/maddpg_matd3_main.py)); Ronchy with `explore=False` over 100 episodes
([MATD3_runner.py L137](https://github.com/Ronchy2000/Multi-agent-RL)). Both surveyed MADDPG implementations that *lack* it are also the ones with
documented problems: the MADDPG-congestion repo defines `mode()` (deterministic argmax) and **never calls it**
([distributions.py L154](https://github.com/QuanyiLi/MADDPG-Congestion-Control-Based-on-OMNETPP)), and SUMO-DVSL has **no eval path at all**.
*Why it plausibly fixes the decay:* it separates "the policy got worse" from "the training-time stochastic
rollouts got noisier because exploration is still on". Since argmax removes action sampling, the eval curve is a
much lower-variance signal — which is also what makes C3 possible. *Risk:* very low — additive code, no change to
the training loop.

**C3. Replace "single highest-reward episode" with a moving average over a window (or with C2's eval return).**
Evidence: the two mature references **decline to select a best model at all** — MAPPO has **zero** matches for
`best` anywhere in the repo and saves periodically by episode interval ([mpe_runner.py L45–47](https://cdn.jsdelivr.net/gh/marlbenchmark/on-policy@main/onpolicy/runner/shared/mpe_runner.py)),
and pymarl saves by **timestep** interval and logs test-return mean/std without comparing them
([run.py L194–199](https://cdn.jsdelivr.net/gh/oxwhirl/pymarl@master/src/run.py), [episode_runner.py L115–118](https://cdn.jsdelivr.net/gh/oxwhirl/pymarl@master/src/runners/episode_runner.py)).
`revisiting-maddpg` accumulates `eval_returns` during training and **never uses them to select a model**
([main.py L116, L155, L176–178](https://cdn.jsdelivr.net/gh/uoe-agents/revisiting-maddpg@main/main.py)). The two repos that *do* use a best-so-far rule both
aggregate rather than take a single episode: Ronchy compares an **episode mean over the adversary agents**
([MATD3_runner.py L76–79](https://github.com/Ronchy2000/Multi-agent-RL)); SUMO-DVSL compares the raw undiscounted episode sum with a
`==`-against-running-max rule that re-saves on ties ([ddpg0.py L212–213](https://cdn.jsdelivr.net/gh/Kaimaoge/SUMO-DVSL@master/ddpg0.py)). *Why it plausibly fixes the decay:*
it directly addresses the failure mode where the *checkpoint you keep* is a lucky episode while the *policy you
have* is worse — and it makes the "peak" in your curve a property of the policy rather than of one rollout.
*Risk:* very low.

**C4. Add gradient-norm clipping (0.5–1.0 is the best-attested range for this algorithm family).**
Evidence: **0.5** in maddpg-pytorch ([maddpg.py L131, L165](https://cdn.jsdelivr.net/gh/shariqiqbal2810/maddpg-pytorch@master/algorithms/maddpg.py)), Ronchy MATD3 ([TD3_agent.py L81, L87](https://github.com/Ronchy2000/Multi-agent-RL))
and the MADDPG-congestion repo ([maddpg.py L153, L165](https://github.com/QuanyiLi/MADDPG-Congestion-Control-Based-on-OMNETPP)); **1.0** in `revisiting-maddpg`
([agent.py L71, L87](https://cdn.jsdelivr.net/gh/uoe-agents/revisiting-maddpg@main/agent.py)); **10.0** (L2, global) in pymarl ([q_learner.py L102](https://cdn.jsdelivr.net/gh/oxwhirl/pymarl@master/src/learners/q_learner.py)),
MAPPO ([r_mappo.py L148–149](https://cdn.jsdelivr.net/gh/marlbenchmark/on-policy@main/onpolicy/algorithms/r_mappo/r_mappo.py)) and MARL-code-pytorch. *Why it plausibly fixes the decay:* it bounds the
per-update parameter change, which is the standard guard against exactly the late-training divergence described —
and it is the most conspicuous omission relative to comparable projects (the four repos that omit it — SUMO-DVSL,
ramp-metering TD3, cinglelas, sumo-rl's DQN — are also the least stable-looking in this survey). *Risk:* low;
clipping too aggressively (e.g. 0.5 on a large critic) can slow learning, so if the run is already slow, start at
1.0–10.0.

**C5. Decide explicitly whether this is MADDPG or MATD3, and if TD3, ship all three tricks.**
Evidence: **no comparable project has twin critics without also having target policy smoothing and delayed policy
updates.** Ronchy MATD3: twin critics + `policy_noise=0.1`/`noise_clip=0.5` + `policy_freq=3`
([MATD3_agent.py L31–32, L73–76, L149](https://github.com/Ronchy2000/Multi-agent-RL)); MARL-code-pytorch MATD3: twin critics + `policy_noise=0.2`/`noise_clip=0.5` +
`policy_update_freq=2` ([matd3.py L58, L71](https://cdn.jsdelivr.net/gh/yongqingzs/MARL-code-pytorch@main/algorithms/maddpg_matd3_mpe/matd3.py)); highway ramp-metering TD3: tau 0.02 + twin
critics + `POLICY_NOISE=0.2`/`NOISE_CLIP=0.3` + `POLICY_FREQ=150` ([TD3.py L125–133, L142, L150–157](https://github.com/YuHan-Research-Group-SEU/Deep-Reinforcement-Learning-Network-for-Highway-Ramp-Metering/blob/main/Model%20and%20Training/TD3.py));
sac_vsl: twin Q + tau 5e-3 + auto entropy. Conversely, the MADDPG-only repos converge on **soft tau 0.01 and
nothing else** (maddpg-pytorch, MARL-code-pytorch's MADDPG, SUMO-DVSL, MADDPG congestion). *Why it plausibly fixes
the decay:* the twin-critic `min` directly targets Q-overestimation, which is the classic cause of a return curve
that rises and then collapses as the critic drifts. *Risk:* medium — it is the largest change here, and it changes
the algorithm; but it is also the most standardised package in the survey. If the team wants the smallest step,
adopt only the **delayed policy update** first: `mpcrl-for-ramp-metering` deliberately keeps *only* that trick from
TD3 — `policy_delay=lookahead,  # keep only this trick` — while removing the twin critic and target smoothing
([ddpg.py L220–240](https://github.com/FilippoAiraldi/mpcrl-for-ramp-metering)), which is direct evidence that a practitioner judged the delayed update to be the
load-bearing piece.

**C6. Add an explicit learning-starts / warm-up with random actions before any gradient step.**
Evidence: **400 random-action episodes** in `revisiting-maddpg` ([main.py L198, L107–114](https://cdn.jsdelivr.net/gh/uoe-agents/revisiting-maddpg@main/main.py)); **32 episodes** in pymarl
(`can_sample`, [episode_buffer.py L231–232](https://cdn.jsdelivr.net/gh/oxwhirl/pymarl@master/src/components/episode_buffer.py)); **2048 transitions** in ramp-metering TD3 ([run.py L73](https://github.com/YuHan-Research-Group-SEU/Deep-Reinforcement-Learning-Network-for-Highway-Ramp-Metering/blob/main/Model%20and%20Training/run.py));
**1500 steps** in sac_vsl (`num_steps_sampled_before_learning_starts = 1500`); **200 random steps** in Ronchy;
**1024 transitions** in maddpg-pytorch. *Why it plausibly fixes the decay:* a buffer pre-filled with
untrained-policy transitions (SUMO-DVSL's failure mode: learning starts after 64 steps with no random prefill,
[ddpg0.py L190](https://cdn.jsdelivr.net/gh/Kaimaoge/SUMO-DVSL@master/ddpg0.py)) biases early critic targets; that bias is replayed for
hundreds of episodes in a 500k buffer, so early bad data stays influential deep into the run — a clean candidate
mechanism for late-run degradation. *Risk:* very low.

**C7. Consider a decayed learning rate for long runs.**
Evidence: MAPPO implements **linear LR decay to zero** (`--use_linear_lr_decay`, `utils/util.py` L17–21) but leaves
it **off by default**; `mpcrl-for-ramp-metering` uses **exponential LR decay 0.925 per update**; ramp-metering TD3
**imports `ExponentialLR` and never instantiates it** ([TD3.py L5](https://github.com/YuHan-Research-Group-SEU/Deep-Reinforcement-Learning-Network-for-Highway-Ramp-Metering/blob/main/Model%20and%20Training/TD3.py)) — i.e. an
intended-but-unimplemented schedule, which is itself evidence that practitioners reach for this under exactly this
symptom. *Why it plausibly fixes the decay:* late-run degradation is often the policy taking a large, destructive
step on a long-horizon objective; shrinking the step size preserves the good policy found around ep 600–800.
*Risk:* low–medium; if the curve is still improving at the end, decay is wasted, so gate it behind the observed
peak.

**C8. Where a discrete action space is involved, prefer Gumbel-Softmax sampling over plain softmax sampling.**
Evidence: maddpg-pytorch's discrete path uses `gumbel_softmax(action, hard=True)` and the code notes discrete
policies "don't seem to learn properly without it" ([agents.py L67](https://cdn.jsdelivr.net/gh/shariqiqbal2810/maddpg-pytorch@master/utils/agents.py)); the MADDPG-congestion repo likewise uses
`SoftCategoricalPdType` with a Gumbel reparameterisation ([distributions.py L204–206, L322–324](https://github.com/QuanyiLi/MADDPG-Congestion-Control-Based-on-OMNETPP));
and `revisiting-maddpg` exists specifically to study this choice, concluding in its paper that the plain
Gumbel-Softmax estimator's bias "is indeed problematic for MADDPG" while the deterministic-perturbation variant GST
gave "55% higher maximum returns … over double the average returns" ([arXiv:2302.11793](https://arxiv.org/abs/2302.11793)). This is
Conditional on how this project's actor gradient is estimated through its discrete action. *Why it plausibly fixes
the decay:* for a 2-action softmax head, the gradient estimator's bias is a plausible cause of the policy settling,
then wandering. *Risk:* medium — it changes the estimator; treat as a follow-up experiment after C1–C4.

**C9. Report results over several seeds, and say so in the competition write-up.**
Evidence: the closest published analogue averages **10 runs per strategy per service level** ("each strategy was
tested ten times, and the averages were taken as the final results to enhance the validity of the test outcomes",
hu2025jits p.16, 6.2); `revisiting-maddpg` uses **5 seeds with 95% CIs**; `mpcrl` trains **15 parallel seeds**;
`sac_vsl` evaluates **3 scenarios with different seeds**. *Why it matters here:* a single-run "peak at ep 600–800"
is not yet evidence of a real phenomenon. *Risk:* none technically; costs compute. Note the counter-evidence:
SUMO-DVSL, ramp-metering TD3, cinglelas's training code and MAPPO's MPE scripts set **no seeds at all**, so a
competition judge is unlikely to demand multi-seed reporting — but the closest topical paper does it.

### One-line summary for the write-up

No comparable open-source project uses an entropy coefficient anywhere near **5.0** (MAPPO's explicit default is
**0.01**; five of the surveyed MADDPG/MATD3/TD3 codebases use **none**), none selects a checkpoint by a **single best
episode** (the mature references decline to track a "best" model at all, or aggregate over an episode window), and
essentially all of them evaluate a **deterministic** policy — while the closest published analogue, MADDPG for hard
shoulder running with emergency vehicles, reports **no** entropy term, **no** tau, **no** γ, **no** learning rates,
**no** buffer size and **no** checkpoint rule at all. The CA-highway + RL combination itself appears to be
**unoccupied in open source**.
