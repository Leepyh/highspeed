## 2. 这个模型在做什么

### 2.1 仿真对象

三车道**环形**高速公路，L = 1000 元胞，车道 0/1/2 = 超车道 / 行车道 / **应急车道**。

- 社会车辆数 **每回合在 450–600 之间随机采样**（密度 0.45–0.60，属于轻度到严重拥堵）
- 应急车最多 3 辆，出现概率每回合在 0.3–0.5 随机采样
- 元胞自动机规则：加速 `v←min(v+1,v_max)`、刹车 `v←min(v, d_front)`、概率换道（P1=0.6，避让时 P2=0.9）
- 应急车影响范围 D = 40，让行触发距离 60

### 2.2 控制问题（多智能体 MDP）

| 项 | 值 |
|---|---|
| 道路分段 | 5 段 × 200 元胞，**每段 1 个智能体** |
| 动作 | 离散 2 值：**0 = 该段应急车道关闭，1 = 开放** |
| 观测 | `obs_dim = 45` = 5 段 × 8 维（3 车道密度 + 3 车道速度 + 应急车距离 + 应急车速度）+ 5 维历史动作 |
| 决策频率 | 每 3 个 CA 步决策一次（`decision_interval=3`），每回合 500 步 → 167 个决策步 |
| 算法 | MADDPG（每个智能体 1 个 Actor，集中式 Critic） |

**核心机制**：动作不是直接移车，而是"**允许 / 禁止**社会车辆进入应急车道"。
`env_maddpg._install_emergency_lane_gate()` 把分段闸门挂到 CA 的
`_can_enter_emergency_lane` 上，`high.py._can_change_lane()` 调用它；
闸门之上还叠加 CA 自身的物理规则（应急车后方 `yield_distance=60` 内禁止进入）。

> 交接文档记录了一个**致命缺陷已修复**：修复前该回调在 `high.py` 中从未被调用（死代码），
> 导致动作对交通流零影响，`AlwaysOpen` 与 `AlwaysClose` 逐步骤完全相同。现已打通。

### 2.3 奖励函数（`env_maddpg._reward_parts()`）

每个智能体、每个决策步的奖励 = 以下 5 项之和：

| 分项 | 计算方式 | 量级 |
|---|---|---|
| `efficiency` | `20.0 × 全局归一化车速` + `2.0 × 本段社会车道归一化车速`；**若全局拥堵**（<0.6）再 `−2.0 + 20.0 × 全局车速` | ~18（**主导项**） |
| `speed_gain` | `40.0 × max(0, 本步全局车速 − 上一步全局车速)` | ~1 |
| `emergency_speed` | `4.0 × 本段应急车归一化速度`（本段无应急车则 0） | ~0.5 |
| `resource` | 若"本段不需要开放"：动作为关闭 `+1.0`，动作为开放 `−1.0` | ~0.6 |
| `control` | `−0.05 × 动作切换` + `−0.1 × 与相邻段动作不一致` | ~0 |

**设计原则（README 明确写了）**：奖励必须由**动作产生的实际后果**决定，不能由动作本身决定。
旧版有 `emergency_lane_capacity_bonus`、`emergency_vehicle_open_reward` 等
"只要 `action==1` 就无条件加分"的常量项 —— 等于白送分，现已全部置 0。

**两个已修复的、必须知道的坑**：

1. `emergency_speed_weight` 曾为 **15.0**。因为"关闭"时应急车恒为 `v_max=5`，该项在关闭状态下
   近似常数，却压倒真正的任务奖励 → 最优动作在密度区间内**非单调翻转** → 训练退化成"永远关闭"。
   现降到 **4.0**，只承担"别把应急车堵死"的约束作用。
2. 拥堵判定曾用 `_get_segment_info()`，它把**空车道视为畅通（1.0）**。
   而应急车道在关闭时必然为空 → 本段均速被恒定抬高约 1/3 → "需要开放"永不成立 →
   **奖励反而惩罚开放**。现改用 `_local_congestion_speed()`，只统计社会车道。

## 3. 训练策略

| 项 | 设置 |
|---|---|
| 算法 | MADDPG，5 个 Actor（[128, 64]）+ 5 个集中式 Critic（[256, 128, 64]） |
| 学习率 | Actor **3e-5**（从 1e-4 降下来，防策略过早确定）/ Critic 1e-3 |
| 折扣 | γ = 0.95，软更新 τ = 0.005 |
| 回放 | 容量 500,000，batch 128，**每 2 个决策步更新一次**（`train_every=2`，把占单步 76% 的梯度开销摊薄） |
| **熵正则** | `entropy_coef = 5.0` —— Actor 损失额外加 `−5.0 × H(π)` |
| 探索 | ε 从 1.0 起，**每回合** ×0.998，下限 0.05（约 2000 轮到下限） |
| 训练量 | 目标 4000 轮；实际跑到 **第 2740 轮中断**（当前无 Python 进程在跑） |
| 检查点 | 每 200 轮存轻量检查点；每 50 轮存含回放缓冲的续训检查点；**每回合若刷新单回合最高奖励则存 `maddpg_best.pth`** |
| 设备 | CUDA（RTX 5060 Laptop, sm_120, torch 2.9.1+cu128），实测每回合约 4 s |

**熵正则的来龙去脉**（这是本项目最值得写进论文的一段）：
早期 `entropy_coef=0.02` 时熵项只有 0.014，被量级约 400 的 Q 完全压倒（占比 0.003%），
第 400 轮策略熵就坍缩到 **0.0000**（5 个智能体全部恒选"关闭"），`Avg` 从峰值 3569 跌到 3246。
直接把系数提到 5.0 后熵稳定在 0.68 —— **从一个极端滑到另一个极端**：
熵上限是 ln2 ≈ 0.6931，0.68 意味着策略**几乎均匀随机**，学不到东西。
交接文档对此的自我诊断是正确的，它也给了 3 条改进建议（归一化奖励尺度后再定系数 / 下调到 1.0–2.0 / 熵系数退火）。

## 4. 我的评估方法（为什么和项目原来的数字不一样）

### 4.1 原 `evaluate.py` 的三个方法论问题

1. **不配对**：`run_strategy()` 里每个策略各自 `env.reset()` n 次，而每次 reset 会重新随机采样
   `n_cars ~ U{450..600}` 和 `P_emergency ~ U(0.3, 0.5)`。
   结果是**每个策略在完全不同的交通场景上被评分**，50 个回合的采样噪声足以打乱排名。
2. **没有确定性评估路径**：`MADDPGAgent.select_action(obs, evaluate=True)` 里
   `evaluate=True` **只关掉了 ε 随机探索**，动作仍然是
   `np.random.choice(n_actions, p=probs[i])` —— **按概率采样，不是 argmax**。
   在熵 0.68（几乎均匀）的策略下，这个"MADDPG"行实际上在评估一个**近似随机策略**。
   项目里所有历史"MADDPG 排名第 3/6""MADDPG ≈ Always Close"的结论都源于此。
3. **指标是"回合末单帧快照"**：`_episode_metrics()` 在 `while not done` **循环结束之后**才被调用，
   读的是 t=500 那一刻的 `env.ca`。所以 `social_speed`、`emergency_speed`、
   `emergency_stall_steps`、`success` 全都是**单帧采样**，不是回合平均。
   这就是为什么原脚本的应急车均速只有 2.5 左右，而回合平均是 4.6 —— 单帧值噪声极大。
   本次分析的所有速度/承载率指标都是**整回合（167 个决策步）平均**。

**交叉验证**：我原样运行了项目的 `evaluate.py`（未做任何修改）：

```
MADDPG        3252.90   排名 3/6
Random        3429.99   ← 第 1
Periodic      3346.11
Always Open   3208.35
Greedy        2949.92
Always Close  2801.46
```

这与交接文档记载的历史结论（MADDPG 排名第 3、输给 Random/Periodic）**完全一致**，
证明问题确实出在评估口径而非模型本身。用同一份 `maddpg_best.pth`，
换成"确定性策略 + 配对评估"，排名从**第 3/6 变成第 1/8**。

### 4.2 我的评估脚本（全部新增，只读原有代码）

`analysis/eval_paired.py` 做了两件关键的事：

```python
random.seed(seed); np.random.seed(seed); env.reset()   # 场景固定
...
rstate, nstate = random.getstate(), np.random.get_state()
actions = policy(env, obs, step)          # 策略调用期间冻结全局随机流
random.setstate(rstate); np.random.set_state(nstate)
```

- **配对**：同一 seed 下，所有策略的车辆数、应急车概率、初始位置/速度/车道、随机流起点**完全一致**。
  （动作会改变后续随机数的消耗量，轨迹在决策后自然分叉 —— 这属于策略自身造成的不确定性。）
- **隔离**：策略自己的随机性不会污染环境随机流。
- **两条评估口径都测**：`MADDPG_argmax`（确定性，真正"学到的策略"）与
  `MADDPG_sample`（兼容原 `evaluate.py` 口径）。

配对设计让比较灵敏度大幅提升：环境场景方差被抵消，**配对差的 SEM 远小于两个独立均值的 SEM**。

| `\|p−0.5\| < 0.05` 的决策占比 | **27.4%**（紧贴判定边界） |
| 各智能体开放率 | [3.87%, **0.17%**, 5.14%, 0.40%, 0.57%]（严重不均） |
| **有应急车在本段** 时开放率 | **8.24%** |
| 无应急车时开放率 | 0.28% → **相差 29 倍** |
| 开放率（本段车速 0.8–1.0 畅通） | 2.42% |
| 开放率（本段车速 0.0–0.2 最堵） | 0.46% |

**这是一幅很微妙的图景，两条都要说清楚**：

✅ **确实学到了状态依赖** —— 有应急车在本段时开放率是无应急车时的 **29 倍**，
说明 Actor 真的在用观测里的"应急车"特征做决策，不是恒定输出。

⚠️ **但依赖幅度极小** —— `p` 只在 0.428 ± 0.037 之间浮动，**整体压在 0.5 判定线下方**，
27.4% 的决策点离 0.5 不到 0.05。所谓"确定性策略"其实是
**"绝大部分关闭 + 极少量精准开放"**：2% 的决策开放，却把应急道承载率做到 4.59%
（对比 Greedy 开放 21% 却只有 0.25%），并换来社会车速 2.061 → 2.637（+28%）。

**含义**：这个模型处在"**高熵、弱状态依赖、靠稀疏精准动作取胜**"的区间。
它表现好是真的，但**稳定性储备很薄** —— 网络精度/扰动的微小变化就可能让 argmax 整体移向"恒关闭"
（那正是第 1000 轮之后的退化形态）。这是写进材料时必须诚实交代的一条。

### 5.5 一个值得写进论文的机制发现

`Greedy`（本段堵就开放）和 `Always Close` 的实测结果**几乎完全一样**：
社会车速同为 2.061，应急道承载率同为 0.25%，开放率却高达 21%。

原因：CA 的换道条件要求"**受阻**"（`d(t) < v(t)`）且车辆处于匀速态。
**在最堵的段，车速 v 很小，"d < v"反而难以成立** → 车根本换不进去。
所以"哪里堵开哪里"这个看似合理的直觉策略是**无效**的；
真正有效的是**在还能换道的时刻/位置精准短开**（这正是 argmax 策略在做的事）。
这条对照恰好从反面论证了"多智能体学习控制"的必要性。

## 8. 必须知道的 7 条风险 / 待办

1. **`maddpg_best.pth` 的挑选标准有缺陷**。训练脚本按"**单回合最高奖励**"存 best，
   而单回合奖励方差很大（本例 SEM ≈ 47，单回合标准差约 300+），
   挑中的往往是"运气好的一轮"而不是"最好的策略"。这次恰好挑中了真最优，
   **是运气不是方法**。建议改为按最近 N 回合滑动平均存档。
2. **`evaluate.py` 没有确定性评估路径**（`evaluate=True` 仍在采样）。
   项目历史所有"MADDPG 排名第 3""MADDPG ≈ Always Close"的结论都是这个口径造成的假象。
   建议给 `select_action` 加一个真正的 `deterministic=True` 分支。
3. **`evaluate.py` 不配对**，且**速度类指标只取回合末单帧**。建议按 `analysis/eval_paired.py` 重写。
4. **第 1000 轮后 argmax 策略退化为"近乎恒关闭"**（奖励 2920 ≈ AlwaysClose），
   但采样策略的熵仍正常（0.65–0.68）。说明"熵不坍缩"**并不等于**"策略没退化"——
   现有 `tools/check_policy_entropy.py` 只看采样熵，**漏掉了这个失效模式**。
   建议该工具增加 argmax 开放率作为第二判据（健康的 argmax 开放率应在 1%–10% 量级，而不是 0%）。
5. **训练在 2740 轮中断**，`models_matd3/maddpg_resume.pth`（807 MB，第 2700 轮）是最新状态。
   若继续训练，按第 4 条可知大概率还会停在退化平台上 —— 建议先按交接文档 §7.1 的方案 1
   （先归一化奖励尺度，再定 `entropy_coef`）调整后再训，否则 5 小时白跑。
6. **策略的稳健性储备薄**（§5.4）。当前优势建立在"p 紧贴 0.5、2% 稀疏开放"上，
   建议在材料里作为"当前最优 + 已知局限"来陈述，并补一个
   "对观测加扰动的鲁棒性测试"以量化它。
7. **指标冗余**：`success_rate` 在所有策略上都是 100%
   （阈值 `emergency_min_acceptable_speed=2.0` 太低，实际应急车均速都 ≥ 3.17）。
   该指标不具区分度，图中保留只为完整性；若要用于论文建议调高阈值或改成分布型指标。
