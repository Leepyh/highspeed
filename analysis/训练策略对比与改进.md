## 2. 逐项对照（这是重点）

### 2.1 ⚠️ 最关键的一条：Actor 更新时喂给 Critic 的到底是什么

**openai/maddpg 的原文**（`make_update_exp` 之前的 `p_train`）：

```python
act_sample  = act_pd.sample()
p_reg       = tf.reduce_mean(tf.square(act_pd.flatparam()))

act_input_n = act_ph_n + []
act_input_n[p_index] = act_pd.sample()          # <<<< 这一行
q_input     = tf.concat(obs_ph_n + act_input_n, 1)
q           = q_func(q_input, 1, ...)[:, 0]
pg_loss     = -tf.reduce_mean(q)
loss        = pg_loss + p_reg * 1e-3
```

`act_input_n[p_index]` 被替换成 **`act_pd.sample()`** —— 也就是**从当前策略里采样出来的
一个实际动作**（离散动作空间下就是独热向量），其余智能体用的是回放缓冲里**实际执行过的动作**
（同样是独热）。**critic 始终在"真实动作"上被求值。**

**本项目修复前的写法**（`maddpg_v2.learn()`）：

```python
parts = [self.actors[j](obs_tensor[:, j, :]) for j in range(n_agents)]   # 软概率
joint = torch.stack(parts, dim=1)                                        # [π0,...,π4]
q = self.critics[i](obs_flat, joint.reshape(bs, -1)).mean()              # 喂给 critic
```

喂进去的是 **5 个 Actor 的软概率向量**，而 critic 的**训练**用的是
`F.one_hot(action_tensor)`（独热）。**critic 在训练时从没见过软向量**，
用它去评价软向量，等于在一个从未拟合过的输入点上取梯度。

**这就是"actor 学不到东西"的根因**，也解释了实测现象：
策略概率长期贴在 0.5 附近（实测 |p−0.5|<0.05 占 27.4%），
argmax 只是在读噪声，所以相邻检查点排名乱跳、第 600 轮后不再改善。

**顺带**：参考实现还有一个 `p_reg = mean(flatparam²) × 1e-3` ——
对**分布参数**加一个极小的 L2 正则，作用是**别让 logits 跑太远**。
注意它是 1e-3 量级，而且**不是熵奖励**。本项目用的是 `entropy_coef = 5.0` 的
**熵奖励**，量级差了三个数量级，方向也相反（熵奖励鼓励随机，L2 只是限制幅度）。

### 2.2 目标 Q 用的动作

**PyMARL**（Q 学习，天然只在离散动作上取值）：

```python
cur_max_actions  = mac_out_detach[:, 1:].max(dim=3, keepdim=True)[1]
target_max_qvals = th.gather(target_mac_out, 3, cur_max_actions).squeeze(3)   # 离散索引取值
```

**TD3**（连续动作，但目标动作仍在合法动作空间内）：

```python
noise = (torch.randn_like(action) * self.policy_noise).clamp(-self.noise_clip, self.noise_clip)
next_action = (self.actor_target(next_state) + noise).clamp(-self.max_action, self.max_action)
```

**本项目修复前**：`next_actions = self._actor_probs_target(next_obs_tensor)` —— 又一次把
**软概率向量**喂给 target critic。同一类分布外求值问题。
另外配置里那两个 `target_noise / target_noise_clip` 键**从未被使用**（死配置）。

### 2.3 探索：线性退火 vs 指数衰减

**PyMARL**（`src/config/algs/qmix.yaml` 原文）：

```yaml
action_selector: "epsilon_greedy"
epsilon_start: 1.0
epsilon_finish: 0.05
epsilon_anneal_time: 50000
```

**线性**从 1.0 退到 0.05，时长用步数明确指定。
本项目原来用 `ε ← ε × 0.998` 指数衰减：第 1000 轮还有 13.5%，第 2000 轮就压到
下限 0.05 —— **前期探索过慢、后期探索提前结束，两头都不均匀**。

### 2.4 学习前的预热

**TD3**（`main.py` 原文）：

```python
parser.add_argument("--start_timesteps", default=25e3, type=int)  # 前 25000 步纯随机
...
if t < args.start_timesteps:
    action = env.action_space.sample()
...
if t >= args.start_timesteps:
    policy.train(replay_buffer, args.batch_size)
```

**openai/maddpg**：

```python
self.max_replay_buffer_len = args.batch_size * args.max_episode_len
...
if len(self.replay_buffer) < self.max_replay_buffer_len:   # 缓冲不够就直接不学
    return
```

**本项目修复前**：`if len(self.buffer) < self.config['batch_size']: return` ——
只要缓冲里有 **1 个 batch（128 条 ≈ 0.8 个回合）** 就开始梯度更新，
critic 早期基本是在拟合随机初始化的 target。

### 2.5 其它差异一览

| 项 | 本项目（修复前） | 参考实现 | 证据 |
|---|---|---|---|
| 更新频率 | 每 **2 个决策步** | MADDPG：`if not t % 100 == 0: return`（每 100 步） | `maddpg.py` |
| 目标网络 | 软更新 τ=0.005，每次更新都做 | MADDPG：`polyak = 1.0 - 1e-2` → **τ=0.01**；PyMARL：`target_update_interval: 200`（**每 200 幕硬替换**） | `maddpg.py`, `qmix.yaml` |
| 梯度裁剪 | `max_grad_norm = 1.0` | MADDPG：`grad_norm_clipping=0.5` | `maddpg.py` |
| 双重 critic | 无 | TD3：`target_Q = torch.min(target_Q1, target_Q2)`；PyMARL：`double_q: True` | `TD3.py`, `qmix.yaml` |
| 延迟策略更新 | `policy_freq = 2` ✅ 已有 | TD3：`policy_freq=2` | `TD3.py` |
| 奖励处理 | 未归一化（Q 量级 ~400） | 三者均**未显式归一化奖励** | 三份源码 |
| **best 模型挑选** | **单回合最高奖励** | **两者都没有 best 挑选**：PyMARL 按 `save_model_interval` 定期存；TD3 `if args.save_model: policy.save(...)` 在每个 eval 点存。PyMARL 的 resume 靠 `checkpoint_path` 指定时间步 | `README.md`(pymarl), `main.py`(TD3) |
| **评测协议** | 各策略各自随机场景；用**采样**策略；指标取**回合末单帧** | TD3：`eval_env.seed(seed + 100)` **固定评测种子**、单独评测环境、`eval_episodes=10`、`select_action` 是**确定性输出** | `main.py`(TD3) |
| 随机种子 | 训练设种子，评测不设 | TD3：`env.seed / action_space.seed / torch.manual_seed / np.random.seed` 全部设置 | `main.py`(TD3) |

## 3. 本次实际做的修改

> **奖励函数完全没动**：`config_maddpg.ENV_CONFIG['reward_weights']` 15 个键、
> `env_maddpg._reward_parts()` 的计算方式，与备份逐字节一致（已用 AST 解析比对验证）。

| # | 修改 | 依据 | 文件 |
|---|---|---|---|
| 1 | **Actor 更新改为"反事实期望 Q"**：其余智能体保持本批次**实际执行的独热动作**，只把第 i 个动作分别设为 0/1，得到 Q(s,a_i=0)、Q(s,a_i=1)，再按当前策略概率加权 | openai/maddpg 用 `act_pd.sample()` 保证 critic 在真实动作上求值 | `maddpg_v2.py` |
| 2 | **目标 Q 改为独热 argmax + 离散版目标策略平滑**（`target_flip_p=0.1` 概率翻转） | PyMARL 用 `gather` 在离散动作上取值；TD3 的平滑噪声加完仍在动作空间内 | `maddpg_v2.py`、`config_maddpg.py` |
| 3 | **熵系数线性退火** 1.0 → 0.05（800 轮走完），不再固定 5.0 | 固定 5.0 会把策略永久钉在均匀分布附近；参考实现根本不用熵奖励，只用 1e-3 的 L2 | `config_maddpg.py` |
| 4 | **ε 改线性衰减** 1.0 → 0.05（800 轮） | PyMARL `epsilon_anneal_time` 线性退火 | `config_maddpg.py` |
| 5 | **best 改为滑动平均挑选**（`maddpg_best_avg.pth`），单回合最高分另存 `maddpg_best_peak.pth` | 参考实现都不按"单回合最高"挑；单回合奖励标准差 300+，最大值是运气不是策略 | `maddpg_v2.py` |
| 6 | **训练日志新增 `ArgmaxOpen / Entropy / EntCoef`**，每 10 轮一行；新增 `[probe]` 行 | 上一版"采样熵正常但 argmax 已退化"的失效模式完全不可见 | `maddpg_v2.py` |
| 7 | **输出目录改 `models_v2`/`logs_v2`；不再写 `maddpg_best.pth`** | 从零训练只要有一轮超过 3851 就会覆盖现有最优模型 | `config_maddpg.py`、`maddpg_v2.py` |

### 3.1 前文发现的 4 个坑的修复位置

| 坑 | 修复 |
|---|---|
| `select_action(evaluate=True)` 只关 ε、仍按概率采样，没有确定性评估路径 | `select_action(..., deterministic=True)` 取 argmax；`evaluate.py` 默认走它 |
| `evaluate.py` 各策略各自随机场景 | `evaluate.py` 默认**配对**：同一 seed 列表，策略调用期间冻结全局随机流 |
| 指标是回合末单帧快照 | 改为**整回合逐决策步平均** |
| `check_policy_entropy.py` 看不到 argmax 退化 | 三层判据：熵 → argmax 开放率 → **与恒关闭/恒开放做配对对照**（退化时奖励会掉到与恒关闭持平，这个判据抓得到） |

### 3.2 验证

- **单元测试** `analysis/test_actor_update.py`：用"只在独热输入上有效"的 stub critic 复现旧行为的失明——
  ```
  旧更新: p(open) 0.5177 -> 0.5177   （梯度恒为零）
  新更新: p(open) 0.5177 -> 0.9913
  ```
  并且验证熵系数的效果与理论 σ(ΔQ/β) 一致（β=5 时 p=0.538，正好落在实测的 0.43~0.50 区间内）。
- **健康度工具**对已知坏检查点的实测：
  ```
  maddpg_best.pth (ep664, 健康)      : vs恒关闭 +521   -> WARN/PASS
  maddpg_episode_1800.pth (已退化)   : vs恒关闭   -8   -> FAIL   ✅ 抓到了
  ```

## 4. 参考实现里还有、但我**这次没做**的改动（留给下一步）

按"性价比 / 风险"排序：

1. **学习前预热**（TD3 `start_timesteps=25e3`）——已加配置项
   `TRAIN_CONFIG['learn_start_episodes']`，**默认 0（关闭）**以保持本次实验口径一致。
   想试参考做法就改成 30。
2. **双重 critic + 取 min**（TD3）——抑制 Q 过估计，是最能提升长期稳定性的单项改动，
   但要改网络结构与更新逻辑，**本次未做**（改动面大，需要独立验证）。
3. **梯度裁剪 1.0 → 0.5**（openai/maddpg 原值）——一行改动，收益不确定。
4. **目标网络硬更新**（PyMARL 每 200 幕）替代软更新 τ=0.005 —— 与主流连续控制做法相反，
   但对离散动作的 Q 学习更常见。

## 5. 补充：一次独立调研的关键结论

除我自己的抓取外，本次还委托了一次**独立调研**（覆盖 15 个开源仓库 + 2 篇论文），
原文见 `analysis/开源项目训练策略调研（独立调研原文）.md`（94 KB，每条结论都带 URL）。
这里只摘出与本项目直接相关、且**独立佐证了上面改动**的四条：

1. **`entropy_coef = 5.0` 远超业界任何取值。** 该调研查到 MAPPO 官方实现
   `entropy_coef` 默认 **0.01**；被调查的 5 个 MADDPG/MATD3/TD3 代码库
   **根本不用熵项**（pymarl 全文 grep `entropy` 零命中；maddpg-pytorch 只有一个
   `×1e-3` 的 logits L2 惩罚）；用到熵的最大值是 sumo-rl PPO 示例的 **0.1**。
   **5.0 比 MAPPO 默认值大 500 倍，比见过的最大值大 50 倍。**
   → 独立支持本次"熵系数线性退火 1.0→0.05"的改动（我甚至比它建议的更保守）。

2. **没有任何成熟项目按"单回合最高奖励"挑 best。** MAPPO 仓库全文 grep `best`
   **零命中**；pymarl 按时间步存快照、只记录不排名；revisiting-maddpg 累积
   `eval_returns` 却从不使用。唯一接近本项目规则的是 SUMO-DVSL 的
   `if all_ep_r[ep] == max(all_ep_r) and ep > 15` —— 而那是一个
   **主动删掉全部探索、回放池只有 64 条**的仓库。
   → 独立支持本次"改为滑动平均挑选"的改动。

3. **确定性评估几乎是标配。** pymarl 在 `test_mode` 里强制 `epsilon = 0.0`（贪心）；
   MAPPO 调 `deterministic=True`；maddpg-pytorch 用 `explore=False`；
   MARL-code-pytorch 评估时 `noise_std=0`；Ronchy 的 MATD3 用 100 回合 `explore=False`。
   → 独立支持本次"新增确定性 argmax 评估路径"的修复。

4. **主题最接近的工作是一篇没有代码的论文，而且比本项目还不透明。**
   Hu et al. (2025), *Optimization of hard shoulder running on highways using
   multi-agent reinforcement learning considering emergency vehicles*,
   J. Intelligent Transportation Systems
   ——[论文页](https://www.tandfonline.com/doi/full/10.1080/15472450.2025.2543823) ·
   [作者 PDF](https://sunderlandaj-1130.github.io/files/hu2025jits.pdf)。
   它做的事与本项目几乎同构（**硬路肩/应急车道离散开关 + MADDPG + 应急车辆**，
   济南绕城高速 SUMO 案例），但论文里
   **没有给出熵项、ε 取值、τ 取值、γ 取值、学习率、batch、buffer、检查点规则、
   随机种子、是否确定性评估**——也就是说，它**不能**为本项目此前的
   `entropy_coef=5.0` 或"单回合最高分存 best"提供任何先例。

> **该调研明确声明的局限**（我原文照录，不做美化）：
> 它**没有看到本项目的代码**，所以"本项目"那一列完全来自我给它的任务描述；
> 部分 star 数来自第三方镜像（GitHub API 被限流 403）；
> 它**没有找到**任何"离散 MADDPG、先升后降退化"的修复案例，
> 因此它的改动建议属于**邻近实践的类推**，不是已被验证的因果。
> 另外它搜索 **10 次都没找到"元胞自动机 + 强化学习"的开源项目**，
> 也没找到硬路肩 RL 的开源实现——只能说"没搜到"，不等于"不存在"。

### 5.1 调研提出、但本次**没有采纳**的建议（及原因）

| 建议 | 为什么没做 |
|---|---|
| 把 `entropy_coef` 直接降到 ~0.01 | 我采用**退火**到 0.05，保留前期探索能力；直接降到 0.01 有重新触发"第 400 轮熵坍缩"的风险 |
| 加 twin critic + `min(Q1,Q2)` | 改动面大（网络结构 + 更新逻辑），需要独立验证；已在 `训练策略对比与改进.md` §4 列为下一步 |

| 梯度裁剪从 1.0 降到 0.5 | 调研给出的参考区间是 0.5–1.0，本项目 **1.0 已在区间内**，无需改动 |
| 学习前预热 | **已加为配置项** `TRAIN_CONFIG['learn_start_episodes']`（默认 0 = 关闭，保持本次实验口径一致；改 30 即启用） |

### 6.2 结论强度的边界

- 我**没有**找到与"高速公路应急车道分段开关 + 元胞自动机 + MADDPG"完全同构的
  开源仓库。§2 的对照是拿**算法层面的权威实现**做的
  （MADDPG 原作者、QMIX 框架、TD3 原作者），而不是某个来路不明的小仓库。
- §2.1 那条"Actor 更新喂软向量是根因"的判断**不是靠对照推出来的**，
  而是我**自己写单元测试证明了**（`analysis/test_actor_update.py`：
  旧更新在"只认独热输入"的 critic 上梯度恒为零）。
  参考实现的写法只是**旁证**。
- "退化"这个现象本身，我只在**本项目的检查点**上验证过（14 个检查点的配对评估）；
  §5 的调研明确说它**没找到**任何报告同类症状的开源项目，
  所以"这个改法能修好它"目前是**基于机制的推断**，最终仍要以本次训练结果为准。

## 7. 三轮训练的实验结果（**结论：这次的改动没有真正修好问题**）

我按上面的分析跑了三轮对照训练（每轮 400–800 轮，全部写在新目录，旧模型零风险），
并用配对种子的**确定性 argmax** 评估逐检查点筛查。

### 7.3 三个必须承认的结论

1. **没有做出统计上明确更优的模型。**
   `runA ep200` 在两个独立区间都优于旧最优（+28.4 / +108.4），合并 +78.4，
   但置信区间跨 0，**只能说"大概率略好"，不能说"显著更好"**。

2. **我关于熵系数的假设被自己的实验证伪了。**
   我原本认为"熵退火到 0.05 太低 → 策略锁进'大家都关'的均衡"，
   并预测"把熵固定在实测最优区间 ≈0.8 能稳住"。
   为此专门跑了 runC（常数 0.8）——**它在每个可比检查点上都比 runA 更差**，
   而且在 ep200–300 时它的熵系数还**高于** runA。
   所以 §7.1 里"熵越低越差"只是**相关，不是因果**。

3. **真正的主导因素是"检查点之间的巨大波动"，而不是某个可单点修好的 bug。**
   四轮训练产出的检查点全部散落在 **2920–3382** 区间内，波动幅度 ±400；
   而训练策略改动带来的差异（+78）**小于这个波动**。
   这解释了为什么"第 600 轮之后不理想"看起来像退化，却总也修不掉：
   它更像是**同一训练过程内部的检查点方差**在起作用。

### 7.4 那么这次到底得到了什么

| 产出 | 价值 |
|---|---|
| **确定性 argmax 逐检查点筛查流程** | **最大的一项**。旧口径会挑到 runA 的 ep800（2923），筛查挑出 ep200（3382）—— **差距 +459，远大于任何调参收益** |
| 反事实 actor 更新 | 建议保留。runB 用旧更新时 ep200 之后**永久塌到 2920–2950 再没恢复**，runA 撑到 ep300 才回落——**系统性差异，不是运气**（配对检验 p<0.001） |
| 单元测试 `analysis/test_actor_update.py` | 证明旧 actor 更新在"只认独热输入"的 critic 上梯度恒为零；新更新 p(open) 0.5177→0.9913 |
| `tools/check_policy_entropy.py` 三层判据 | 实测能抓出旧 run 的 ep1800（vs 恒关闭 −8 → FAIL） |
| `evaluate.py` 配对 + 确定性 + 整回合平均 | 修掉三个方法论坑；原样跑旧脚本可复现"MADDPG 排名第 3"，换新口径同权重变第 1 |
| **一个统计上不显著的 +78** | 诚实地说：方向为正，证据不足以宣称改进 |

### 7.5 下一步真正该做的（按价值排序）

1. **把"逐检查点 argmax 筛查"固定成流程**——这一条已经被证明值 +459。
2. **多随机种子训练**（参考实现普遍 5–10 个种子取均值）：单次训练的检查点波动
   已经大于任何调参收益，单条曲线不足以支撑结论。
3. **评估场景数从 64 提到 150+**，否则 +78 这种量级的差异永远测不出来。
4. 若要继续改算法：优先 **twin critic + min(Q1,Q2)**（抑制 Q 过估计，
   是"先升后降"最经典的成因），其次**学习前预热**
   （`TRAIN_CONFIG['learn_start_episodes']` 已加好，改成 30 即启用）。
   **不要再调熵系数**——退火和常数 0.8 两个方向都已实测失败。
5. **奖励函数没有动**（按要求）。但要记录一个结构性观察：
   `resource`（关闭 +1）与 `emergency_speed`（关闭时应急车恒 5.0 → 贡献 +4×1.0）
   让"关闭"有**直接的个人收益**，而"开放"的收益是**全局公共品**。
   若将来允许改奖励，这是第一个该动的地方。
